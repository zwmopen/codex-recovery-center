# 产品设计

## 初衷

Windows 版 Codex 在 GPU 子进程失败后，可能继发机器级 AppX 状态异常。用户看到的只有“应用有问题、请重新安装”，旧批处理窗口还会闪退，导致反复运行官网引导安装器和微软商店更新。

恢复中心把判断、等待和官方源恢复变成一个独立界面。即使 Codex 无法启动，它仍能运行。

## 用户与目标

- 用户：使用 Microsoft Store 版 `OpenAI.Codex` 的 Windows 用户。
- 目标：不用终端、不猜黑框；清楚看到当前状态；一键完成安全启动、注册修复和官方商店重新暂存。
- 不做：修改 Codex 程序文件、绕过证书校验、强制替换显卡驱动、静默清空用户数据。

## 关键取舍

1. **独立 EXE**：不依赖 Codex 自身进程，崩溃后仍可打开。
2. **状态驱动**：包为 `Ok` 时不重复注册，避免把正常包主动置入维护状态。
3. **自适应等待**：`NeedsRemediation` 注册后等待 12 秒；其他异常最多等待 30 秒。
4. **同一官方源兜底**：仍异常时调用微软商店产品 `9PLM9XGG6VKS`，与官网引导安装器最终来源一致。
5. **不重置数据**：不调用 `Reset-AppxPackage`。
6. **可验证更新**：只安装公开版本清单声明、且 SHA-256 一致的 Release 文件。

## 视觉真源

本项目不得依据“玻璃”“拟态”等通用词自行发挥，必须以用户已有项目为准：

- 窗口管理器：冷灰蓝背景、同色实体卡片、明暗双阴影和右侧操作组。
- 团建工作流：浅蓝灰内容面、清晰信息层级、克制亮蓝强调。
- 江湖转化助手：低饱和工具界面、紧凑操作密度和有限高光。

1.1.0 的暖灰纸面、墨绿主操作是错误方向，不能再作为参考。

## 两套视觉语言

### 拟态悬浮（默认）

- 画布 `#E8EDF3`，面板 `#E2EAF2`，柔和面 `#DCE4EC`，分隔线 `#D1DBE4`。
- 卡片和按钮使用同色系实体面，不堆纯白卡片。
- 左上浅色高光与右下蓝灰阴影成对出现，形成柔和悬浮实体感。
- WinForms 无法自然生成柔和模糊阴影时，不用硬偏移色块假装投影；小按钮优先使用清晰圆角实体面和轻边界。
- 亮蓝只给“一键恢复并启动”一个主操作；警告和错误只在确有状态时出现。

### 克制玻璃

- 画布 `#DFEAF2`，面板 `#EDF4F8`，使用浅蓝玻璃面与细白边。
- 透明、高光和层叠仅用于帮助区分层级，不使用炫光、大面积透明或高饱和渐变。

## 布局

- 顶部：产品名称、版本、设置与关于。
- 左侧：当前状态、判断说明和恢复路径。
- 右侧：一个主操作与三个次级操作。
- 底部：处理记录入口和本地隐私说明。
- 设置、关于与日志沿用同一主题系统，不出现脱离主界面的系统默认白窗。

继续使用系统 WinForms，不引入网页运行时或第三方 UI 依赖。
