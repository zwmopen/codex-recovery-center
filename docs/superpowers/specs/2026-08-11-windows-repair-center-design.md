# Windows 修复中心 2.0 设计规格

日期：2026-08-11  
状态：设计已确认，等待实现计划  
基线：1.6.0，`main`，`c169a34`  
项目：`D:\AICode\工具开发\projects\codex-recovery-center`

## 1. 产品定位

现有“Codex 恢复中心”升级为“Windows 修复中心”。它是一个只在本机运行的 WinForms 修复工作台，Codex 只是其中一个模块；产品的核心价值是把诊断证据、低风险修复、验证和回滚放在同一条可解释流程中。

第一阶段服务对象是这台用于 Codex、Python、Node、npm/pnpm、同步器和 AI 工具开发的 Windows 电脑。所有诊断默认只读；只有规则明确判定异常时才建议修复。系统不会通过“把所有 PowerShell 窗口隐藏掉”来掩盖根因。

### 不在本阶段做的事

- 不做常驻云端服务、账号体系、遥测或远程控制。
- 不做无法解释的“万能加速”和一键批量删除。
- 不自动删除计划任务、注册表项、启动项或用户数据。
- 不强制终止 Codex、ChatGPT、Node、Python、同步器等开发进程。
- 不把现有脚本复制成第二套长期维护源码；脚本适配器优先调用现有权威脚本。

## 2. 用户体验与视觉约束

### 2.1 主界面

采用“健康总览 + 左侧模块导航”的 A 布局：

- 顶部显示“Windows 修复中心”、版本、设置和关于。
- 左侧显示总健康状态、当前建议和模块列表。
- 右侧显示当前模块的证据、主操作、次级操作和日志入口。
- 首屏提供“开始检查”而不是直接“全部修复”；扫描结束后明确区分正常、建议处理、需要确认和不支持。

### 2.2 视觉真源

继续使用现有 `ProductExperience.cs` 的两套主题，不引入第三套视觉语言：

- 默认拟态悬浮：画布 `#E8EDF3`，卡片 `#E2EBF1`，边界 `#C3D0DC`，文字 `#1C2938`，次要文字 `#606F80`，主操作蓝 `#307EFF`。
- 克制玻璃：沿用项目现有浅蓝玻璃面板、细白边和有限高光。
- 主操作只使用亮蓝；警告、危险和禁用状态使用现有橙/红色体系。
- 保留 YaHei UI、DPI 感知、圆角实体面和原有阴影规则；不使用大面积白卡、暖灰纸面、墨绿主色或高饱和渐变。

### 2.3 反馈原则

每个修复动作都要呈现“正在做什么、为什么做、完成后验证了什么”。长操作显示进度和可取消状态；失败时保留已完成步骤、错误原因和下一步，不只显示红色失败标签。

## 3. 架构方案

采用单 EXE 的模块化单体。第一阶段不引入插件加载、Windows 服务或额外守护进程；这样可保留便携式交付、源码热更新和现有单实例行为，同时让后续模块有稳定边界。

### 3.1 可复用外壳 `WindowsToolShell`

外壳负责与具体修复无关的公共能力：

- 单实例、窗口唤醒、主题、DPI 和导航。
- 模块注册、统一扫描队列、操作状态和取消。
- 权限提示、管理员重启、确认对话框。
- 本地日志、脱敏诊断报告、备份清单和回滚入口。
- 版本信息、源码优先启动、更新和桌面快捷方式维护。

现有 `MainForm.cs`、`ProductExperience.cs`、`ResourceGuard.cs` 和入口逻辑继续作为迁移基础，不另建平行源码目录。

### 3.2 模块契约

每个模块实现统一的生命周期：

```text
模块元数据
  -> DetectAsync()        只读诊断
  -> Evidence             时间、来源、命令/脚本、父子关系、风险等级
  -> PlanRepair()         生成低风险动作或需要确认的动作
  -> ApplyAsync()         执行已确认动作
  -> VerifyAsync()        重新读取状态并判断是否恢复
  -> RollbackAsync()      在存在备份/原配置时恢复
```

诊断结果至少包含 `Normal`、`NeedsAttention`、`NeedsConfirmation`、`Unsupported` 四种状态，并带有权限要求、预计耗时、是否可回滚和影响范围。模块不得直接修改 UI；所有 UI 通过外壳消费结果和事件。

### 3.3 证据对象

对弹窗和启动问题，统一记录以下链路：

```text
时间 -> 进程 -> 父进程 -> 命令行 -> 脚本/任务 -> 来源软件 -> 修复/验证结果
```

事件日志只保存必要的事件 ID、时间、进程名、路径和脱敏命令摘要，不保存聊天正文、Token、Cookie 或未脱敏隐私内容。

## 4. 首批模块

### 4.1 Codex 恢复

保留 1.6.0 已验证的 AppX 状态、注册修复、商店回退、GPU 安全启动、崩溃分诊、内存与资源守卫。旧按钮和日志语义迁移到统一模块契约，行为不回退。

### 4.2 蓝牙音频

将现有“蓝牙音频一键修复”脚本作为过渡适配器：

- 诊断当前蓝牙播放端点、默认设备、AudioEndpointBuilder/Audiosrv 状态和最近失败信息。
- 低风险修复重启目标音频端点及相关服务；设备重启前显示目标设备和影响。
- 保留已有设备选择记录和脚本回退路径，成功后重新验证浏览器播放端点。
- 不默认卸载驱动、不清空全部音频设备、不修改与当前设备无关的端点。

### 4.3 鼠标语音输入

整合既有鼠标语音输入技能的权威脚本和隐藏运行包装：

- 检查 PID、心跳、互斥体、任务计划和实际桥接进程。
- 识别 `WeChat Voice X2 Bridge Watchdog` 的真实触发链，区分正常解锁恢复与重复启动。
- 低风险修复使用现有 `run-hidden.vbs`/任务配置，避免蓝色 PowerShell/CMD 窗口；不通过全局隐藏窗口掩盖未知启动源。
- 复核修复后心跳、单实例和任务最近运行结果。

### 4.4 PowerShell/CMD 弹窗与启动项审计

建立只读证据链，覆盖：Task Scheduler、Startup、Run/RunOnce、PowerShell profile、服务、BAT/CMD/VBS/PS1、Windows Event Log、PowerShell Operational Log，以及现有进程创建日志。

- 首次扫描只列出命中项、最后修改时间、动作命令、来源路径和签名/信任判断。
- 仅对已知且确认无用的遗留启动项提供停用计划；删除必须先备份并二次确认。
- 对合法但显示方式错误的任务，提供后台无窗口启动方式迁移，并验证退出码和下次触发。
- 日志不足时提供“下次捕获模式”：只开启必要的进程创建/PowerShell 记录，明确增加的日志量和关闭入口。

### 4.5 网络诊断与安全优化

“网络优化”定义为可测量的本机健康检查，不承诺不透明的网速提升：

- 读取 DNS、代理、网卡链路、默认网关、Winsock、网络配置文件、Cloudflare/tunnel 状态和最近失败。
- 低风险修复：清理可安全清理的 DNS 缓存、重置指定网络服务状态、刷新租约，并在每步后验证。
- 高风险动作（改 DNS、重置 Winsock/IP、禁用代理或隧道、重启网卡）单独确认，执行前保存原配置。
- 不改变开发环境所需的代理、Cloudflare、隧道或本地端口，除非用户明确选择目标。

### 4.6 电脑加速与资源治理

复用 1.6.0 的资源守卫，再增加可解释的低风险治理：

- 扫描启动项、临时文件、回收站可释放空间、页面文件压力、内存和磁盘占用。
- 清理只针对明确的临时目录和可重建缓存；显示预计释放空间和路径。
- 对重复的 Node/Python/PowerShell/浏览器/AI 后台进程只提供分组提示，默认不杀进程。
- 保留开发工作区白名单和当前活跃父子进程链，避免关闭 Codex、同步器、Vite、Cloudflare tunnel 等正在工作的任务。

### 4.7 启动项与桌面入口治理

统一检查启动文件夹、注册表 Run/RunOnce、计划任务和桌面快捷方式，支持备份、停用、恢复和来源查看。桌面迁移在新版本验证通过后执行：

1. 创建新的 `Windows 修复中心.lnk`，指向源码优先启动器。
2. 将旧的 `Codex 恢复中心.lnk`、`一键修复蓝牙音频.lnk`、`鼠标语音输入-启动修复.lnk` 迁移到本地可恢复备份目录。
3. 只有快捷方式被确认不再需要时才从桌面移除；源代码和脚本不删除。
4. 在应用的“入口管理”中显示迁移记录和恢复按钮。

## 5. 数据流与安全边界

一次“智能检查”按模块并行读取，再按风险排序展示；“一键修复”只执行已标记为低风险且通过前置条件的动作。高风险动作拆成单独确认项，不允许通过“全选”绕过说明。

本地数据统一放在 `%LOCALAPPDATA%\\WindowsRepairCenter`，分为 `settings.ini`、`logs`、`reports`、`backups`、`resource-guard` 和 `updates`。迁移期兼容读取 `%LOCALAPPDATA%\\CodexRecoveryCenter`，成功迁移后保留只读兼容数据，不静默删除旧目录。

每次变更生成操作记录：开始时间、模块、动作、目标、备份位置、结果、验证结论和回滚入口。日志保留周期沿用现有本地策略，不上传外部服务。

## 6. 源码优先开发与交付

开发时桌面入口固定指向源码优先启动器：

- 启动器检查 `src` 与当前 EXE 的更新时间和构建指纹。
- 源码更新时自动调用现有 `scripts\\Build.ps1`；构建成功运行新 EXE，构建失败则启动最后一个可用版本并显示错误日志。
- 不要求每次源码修改都制作安装包或便携发布包。
- 只有里程碑版本才生成 `releases` 产物、版本清单和 SHA-256。
- 发布前保留旧 EXE 和快捷方式恢复点。

版本、README、CHANGELOG、ARCHITECTURE 和 HANDOFF 在功能交付时同步更新；`.superpowers`、构建目录和日志不进入源码提交。

## 7. 测试与验收

### 单元/模块测试

- 每个模块的正常、异常、无权限、不可用和取消路径。
- 诊断不得修改系统；模拟环境验证计划任务、注册表、服务和脚本适配器。
- 蓝牙、鼠标语音和网络修复动作均需有验证步骤和失败回滚测试。

### 集成验收

- 首屏扫描能并行完成并显示模块级证据。
- 修复前显示影响、权限、备份位置和风险；修复后显示验证结论。
- 已知 PowerShell 弹窗场景能够展示时间、进程、父进程、命令行和脚本来源。
- 运行中的 Codex、Node、Python、同步器、Cloudflare/tunnel 不会被默认终止。
- 两套原有主题、DPI、单实例和日志窗口回归通过。
- 源码更新时间变化能触发本地自动构建，构建失败能回退旧版本。
- 新桌面快捷方式指向正确入口，三个旧入口可从备份目录恢复。

### 真实机验收

在当前电脑上分别验证：蓝牙耳机浏览器播放、鼠标语音输入单实例、PowerShell/CMD 弹窗捕获、网络诊断、临时文件清理、资源守卫和桌面入口迁移。所有会改变系统的动作保留前后状态快照。

## 8. 分阶段范围

### P0：统一外壳与已知问题闭环

统一导航、总览、模块契约、日志/证据、Codex 迁移、蓝牙适配器、鼠标语音适配器、PowerShell 弹窗审计、源码优先启动和桌面快捷方式迁移。

### P1：个人电脑优化

网络诊断与低风险优化、启动项治理、临时文件/缓存清理、资源治理白名单、报告导出和可恢复备份浏览。

### P2：增强监控

在 P0/P1 真实机稳定后，再评估按需启用的进程创建捕获、历史趋势、规则版本管理和更多设备模块。P2 不阻塞 P0/P1 交付。

## 9. 已知风险与决策

- Windows 版本、管理员权限、设备驱动和第三方脚本差异可能导致某些修复不可用；模块必须显示 `Unsupported` 和手动路径。
- 网络重置和设备重启存在短暂断连，必须单独确认并保存原配置。
- 自动构建可能失败；始终保留最后一个可用 EXE，不能让桌面入口指向半成品。
- 旧脚本作为适配器期间会有两套运行时边界；迁移完成前以原脚本真实行为和测试结果为准，不复制逻辑。

本规格明确选择：模块化单体、单 EXE、源码优先热更新、原有视觉风格、证据优先和低风险默认修复。实现计划应按 P0 再 P1 拆分，不在第一轮引入插件系统或云端能力。
