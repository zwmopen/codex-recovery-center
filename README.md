# Windows 修复中心

当前版本：2.8.0

这是一个只在本机运行的 Windows 诊断与修复工作台。Codex 是其中一个模块，同时覆盖蓝牙音频、鼠标语音输入、PowerShell/CMD 弹窗来源、网络诊断、启动项、临时文件和开发环境资源治理。所有模块都遵循“先诊断、低风险修复、修复后验证；高风险动作单独确认”的规则。

## 怎么用

双击桌面 `Windows 修复中心`：

- **开始检查**：并行读取各模块状态，显示时间、进程、父进程、命令行、脚本或任务来源等证据。每个模块最多等待 45 秒，单个 Windows 接口异常不会拖住整页。
- **执行建议修复**：只执行当前模块声明的安全动作；修复前显示影响，修复后重新检测。
- **蓝牙音频**：刷新目标音频服务，验证端点状态；不默认卸载驱动。
- **鼠标语音输入**：检查 watchdog、PID、心跳和隐藏任务，必要时只运行已注册任务。
- **PowerShell / CMD 弹窗审计**：读取计划任务（含注册/最近运行时间与动作）、Startup、Run/RunOnce、profile、服务、Security 4688/Sysmon、PowerShell Operational 和实时 shell 父进程；已知工作台来源会归因但不误报，未知启动动作才进入人工确认。
- **网络诊断**：检查 DNS、代理、网卡和 Cloudflare/tunnel；低风险动作只刷新 DNS。
- **存储分析**：只读列出磁盘容量、缓存候选和用户资料边界；绿色缓存可重建，黄色资料只提供路径与大小，不自动删除。
- **强力空间**：集中扫描当前用户临时文件、npm/pnpm/pip/NuGet、浏览器和 VS Code 可重建缓存；清理前显示影响，只处理超过安全保留期且不在项目资料范围内的文件。
- **内置工具包**：运行期诊断、修复、资源守卫和自检代码随 EXE 一起交付；`Build.ps1`、源码启动器和 VBS 只服务开发/热更新，不是发布版的修复依赖。
- **小龙虾**：在同一面板内查看 OpenClaw 运行状态和当前模型，启动、重启、切换 CockpitTools 模型、打开控制网页；桌面不再需要单独的小龙虾面板入口。
- **快捷工具**：把一键安全体检、可重建缓存、DNS、蓝牙音频、释放内存、小龙虾、存储分析、弹窗审计和启动项入口集中到一处；每个动作复用原模块并在有影响时先确认。
- 小龙虾的配置、provider 和密钥仍由本机 `D:\AICode\AI\infrastructure\launchers\manage-openclaw.ps1` 管理；控制脚本缺失时界面会明确提示，不会伪装成已启动。
- **电脑加速与空间**：检查内存、临时文件和开发进程，清理当前用户临时目录中超过 3 天的可重建文件。

- **一键恢复并启动**：Codex 打不开或出现“应用有问题”时使用。工具会关闭残留进程、修复注册；仍异常时调用微软商店官方源重新暂存，恢复后以更稳妥的方式启动。
- **安全模式启动**：安装状态正常，但担心多窗口、旧网页状态或 GPU 渲染再次崩溃时使用。
- **重新检查**：只读取安装与运行状态，不做修改。
- **微软商店修复**：自动恢复没有完成时，打开官方产品页。
- **释放内存**：上次崩溃被判定为内存耗尽、或内存告急时使用。按程序分组列出内存大户，勾选后确认关闭，并显示回收量；系统关键进程不会出现在列表里。
- **资源守卫**：在设置页开启后，每 2 分钟做一次轻量检查。单个 Node/PowerShell 提交内存达到 6 GB 时自动阻断；存活超过 4 小时、失去父进程且句柄异常的开发服务器，以及异常孤儿控制台会被回收。正常 Codex、ChatGPT 和仍在工作的开发服务不会因普通高句柄被关闭。
- **处理记录**：查看本次判断、修复步骤、耗时和结果。
- **设置**：切换拟态/玻璃视觉语言、浅色/深色显示模式，或点击“检查版本”。明暗模式只改变界面，不改变修复逻辑。
- **关于**：查看产品初衷、安全边界、数据与隐私说明。

开发验收可运行 `Windows-Repair-Center.exe --repair-center-self-test <报告路径>`；报告包含各模块耗时、证据数量，以及弹窗审计的少量脱敏证据样本，不写入完整事件日志。

遇到 `Modified, NeedsRemediation` 时，工具先快速确认注册结果；仍未恢复便直接进入微软商店官方重新暂存。商店阶段通常需要 2–4 分钟，界面会持续显示已用时间。

工具不会主动执行 `Reset-AppxPackage`，也不会主动清空 Codex 用户数据。修复会关闭所有 Codex 窗口，使用前先保存正在进行的任务。

恢复中心同一时间只允许运行一个实例。重复双击会唤醒已有窗口，不会并发执行两套 AppX 修复。重新检查时也会读取虚拟内存余量；资源压力高时会在状态区直接提示。

## 两套视觉主题

- **拟态悬浮（默认）**：冷灰蓝背景、同色实体卡片、明暗双阴影，接近窗口管理器的工具感。
- **克制玻璃**：浅蓝玻璃面板、细白边和有限高光，不使用大面积透明或炫光。

显示模式可在设置页切换浅色/深色；深色模式沿用同一套冷灰蓝配色和操作层级，适合长时间使用。

主题会保存在：

```text
%LOCALAPPDATA%\WindowsRepairCenter\settings.ini
```

## 安装与更新

普通用户从 [GitHub Releases](https://github.com/zwmopen/codex-recovery-center/releases/latest) 下载最新 `Windows-Repair-Center-v*.exe`，双击即可运行。

程序会按默认规则发现新版，设置页只保留“检查版本”。新版从公开 Release 下载，必须通过版本清单中的 SHA-256 校验；替换程序前仍需用户确认。

开发者可重新构建并更新桌面入口：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\Build.ps1 -InstallDesktopShortcut
```

## 本地数据

```text
日志：%LOCALAPPDATA%\WindowsRepairCenter\logs
设置：%LOCALAPPDATA%\WindowsRepairCenter\settings.ini
资源守卫状态与脱敏日志：%LOCALAPPDATA%\CodexRecoveryCenter\resource-guard（资源守卫任务为兼容旧版保留此目录）
更新：%LOCALAPPDATA%\WindowsRepairCenter\updates

如果看到 PowerShell 输出乱码：修复中心调用的 Windows PowerShell 会先切换为 UTF-8；请从桌面“Windows 修复中心”入口启动，不要在旧的 Codex 恢复中心副本上操作。
```

项目不会上传聊天内容、凭据或本地诊断日志。

## 已知边界

- 显卡驱动或 Codex 自身 GPU 缺陷仍可能导致运行时崩溃；本工具负责降低风险和恢复可启动状态，不能修改厂商程序代码。
- 资源守卫是最后一道保护，不替代项目自身的退出回收。开发服务仍应使用唯一 PID/端口锁，并在父任务结束时主动退出。
- 微软商店、网络或 App Installer 不可用时，官方源重新暂存可能失败；工具会保留日志并提供官方商店入口。
- 恢复中心无法保证“软件永远不崩”，但能减少重复下载安装器，把常见注册异常变成可观察、可重试、可恢复的流程。
